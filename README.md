# Bot Rm — البحث برقم الموقع

موقع ثابت (PWA) يعمل كتطبيق هاتف. لا يحتاج سيرفر ولا بناء (build).

## النشر على GitHub Pages (مجاني)
1. أنشئ مستودعاً جديداً على GitHub باسم `bot-rm` (Public).
2. ارفع **كل** محتويات هذا المجلد إلى جذر المستودع (Add file ← Upload files).
3. Settings ← Pages ← Source: *Deploy from a branch* ← Branch: `main` / `(root)` ← Save.
4. بعد دقيقة يصبح الرابط: `https://USERNAME.github.io/bot-rm/`

## النشر على Cloudflare Pages (مجاني)
Workers & Pages ← Create ← Pages ← Connect to Git ← اختر المستودع ←
Framework: None، Build command: فارغ، Output directory: `/` ← Save and Deploy.

## تثبيته كتطبيق
- أندرويد (Chrome): ⋮ ← «تثبيت التطبيق».
- آيفون (Safari): مشاركة ← «إضافة إلى الشاشة الرئيسية».

## الدخول
- الدخول مباشر بدون رمز (يمكن تفعيل رمز من الإدارة ← تحديث البيانات)
- الإدارة: المستخدم `Admin` / كلمة المرور `Admin1234`

## تحديث البيانات
الإدارة ← تحديث البيانات ← ارفع ملف الإكسل ← «نشر على GitHub» (بعد إدخال التوكن في الإعدادات)،
أو «تنزيل data.json» واستبدل الملف في المستودع يدوياً.

ملاحظة: الموقع مفتوح للعامة، فأي شخص يستطيع قراءة `data.json`. لحمايته ضع رمز فريق عند رفع التحديث (تشفير AES-256).

## هيكل الكود

```
index.html            الهيكل + مشهد الأبراج (SVG)
config.js / core.js   الإعدادات + قراءة الإكسل والتشفير (مشترك مع سكربت البناء)

js/main.js            نقطة الدخول
js/lib/               dom · storage · text · labels  (أدوات صغيرة)

```

## النشر من لوحة الإدارة (لكل المستخدمين)

زر «نشر للجميع» يرسل البيانات إلى `functions/api/publish.js` (Cloudflare Pages Function) التي تحفظها في KV،
و`functions/data.json.js` يخدم النسخة الأحدث. يتطلب ربط KV namespace باسم `DATA` بالمشروع مرة واحدة:
Cloudflare ← Workers & Pages ← KV ← Create namespace ← ثم المشروع ← Settings ← Bindings ← KV namespace ← Variable name = `DATA`.

## تتبّع الاستخدام والبث (Functions + KV)
- `POST /api/track` يجمّع عمليات البحث يومياً في KV (يتطلب ربط KV باسم `DATA`).
- `GET /api/stats` (إدارة) تقارير كل المستخدمين، و`/api/broadcast` + `/api/bhist` لإعلانات البث.
- ملاحظة: KV المجاني يسمح بنحو 1000 كتابة و100 ألف قراءة يومياً، ولذلك:
  - **القراءة**: البيانات والبحث محليان بالكامل (IndexedDB + الكاش)، والتطبيق لا يطلب `data.json` إلا عند وجود إصدار أحدث.
    طلب واحد خفيف `/api/sync` (إصدار + إعلان) كل 80–100 ثانية أثناء استخدام التطبيق فقط (وعند العودة إليه)، ويُخدم من كاش حافة Cloudflare (20 ثانية)،
    والحزمة نفسها تُخزَّن في الكاش بمفتاح يحمل رقم الإصدار فتُقرأ من KV مرة واحدة لكل إصدار.
  - **الكتابة**: وثيقة واحدة لكل يوم (إحصاءات + آخر العمليات + علامة النسخ الاحتياطي) = كتابة واحدة لكل دفعة؛
    الأجهزة ترسل عند تجمّع 25 حدثاً أو مرور 15 دقيقة (والباقي ينتظر في الطابور المحلي)، والخادم يرفض الدفعات الصغيرة المتقاربة من نفس الجهاز (429).
    النسخة الاحتياطية اليومية لا تُكتب إلا إذا تغيّرت البيانات. عدّاد «كتابات KV اليوم» يظهر في تقارير الإدارة.
  - الأيام القديمة في التقارير تُحفظ في ذاكرة الدالة فلا تُقرأ من KV في كل مرة.
  - بعد النشر أو تغيير الإعلان يُمسح الكاش فوراً في منطقة المدير، ويصل بقية المستخدمين خلال دقيقة.
- سجل التغييرات: عند رفع إكسل جديد (أو تعديل موقع) تُحفظ الفروق داخل صف الموقع (`ch`) مشفّرة، وتظهر في بطاقته.

## الأمان والنسخ
- `POST /api/login` تحقق في الخادم + قفل 15 دقيقة بعد 5 محاولات خاطئة؛ جلسة موقّعة 12 ساعة (السرّ يُولَّد تلقائياً في KV).
- `POST /api/password` تغيير كلمة المرور (يُبطل الجلسات القديمة). `GET/POST /api/versions` سجل آخر 8 نسخ منشورة والتراجع.

## لوحة الإدارة
واجهة كاملة الشاشة: رأس ثابت (حالة الاتصال والجلسة) + قائمة جانبية (تتحول لشريط علوي على الهاتف).
الأقسام: نظرة عامة، التقارير (مؤشرات، طلب حسب المحافظة/الكلستر/الفني، تفاصيل يومية، أنشط الأجهزة، CSV وطباعة)،
التنبيهات، البث، البيانات (رفع إكسل بمراجعة الفروق + تعديل موقع + النسخ والاستعادة)، سجل العمليات (`/api/audit`:
دخول، نشر، استعادة، بث، أمان مع الجهاز والمكان)، الأمان (حالة الحماية، تغيير كلمة المرور، إنهاء كل الجلسات `/api/logoutall`).

### إضافات لوحة الإدارة (أكتوبر 2026)
- **التصحيحات** (تبويب جديد): تعديل ما يراه المستخدمون لموقع واحد (أو إخفاء حقل) مع تاريخ انتهاء اختياري، بدون إعادة رفع الإكسل. تُخزَّن في KV بمفتاح `corr` (كتابة واحدة عند الحفظ)، وتصل للأجهزة عبر رقم إصدار `cv` في `/api/sync` فلا يُجلب الملف إلا عند تغيّره. لا تدخل الحزمة المنشورة ولا مقارنة النشر.
- **فحص الصحة** (`/api/health`): قراءات فقط. **تنزيل البيانات الحالية** كملف `.xlsx` بأعمدة الملف الأصلي (قابل لإعادة الرفع).
- **حدود الاستهلاك**: مؤشرات لكتابات KV وطلبات الخادم (تقدير من عدّادات الأجهزة).
- **الأجهزة والأداء**: جدد/عائدون، نسبة التثبيت، متوسط الفتح والبحث، المتصفحات — كلها تُرسل مع دفعة الإحصاء نفسها (بلا أي كتابة أو طلب إضافي).
- **مؤشر «مباشر»** في الرأس (من آخر الدفعات)، رسوم تنمو عند الظهور، انتقال ناعم بين التبويبات، وهياكل تحميل.

### التحكمات (50 تحكماً)
تبويب **التحكمات** في لوحة الإدارة: وضع الصيانة، البحث (النص/الهاتف/المقاربة/الحدود)، أزرار وأقسام بطاقة الموقع، نصوص الصفحة الرئيسية وعناصرها، فرض المظهر واللون وأنميشن الكتابة، فترة المزامنة وإجبار تنزيل البيانات أو تحديث التطبيق، تتبّع الإحصاءات، ومدة الجلسة ومحاولات الدخول. المخطط في `js/data/controlsSchema.js` (مصدر واحد للخادم والواجهة).
- تُخزَّن في KV بمفتاح `ctl` (القيم المختلفة عن الافتراضي فقط)، كتابة واحدة عند «حفظ التغييرات».
- تصل للأجهزة عبر رقم الإصدار `tv` في `/api/sync` (لا يُجلب `/api/controls` إلا عند تغيّره) وتُحفظ محلياً فتعمل بلا إنترنت.
- الدخول للإدارة وقت الصيانة أو عند إخفاء الزر: افتح `/?admin`.

### صفحة المدير (`/manager.html`)
صفحة مستقلة غير مرتبطة من التطبيق، دخولها باسم المدير عبر `/api/mgr` (التحقق في الخادم، كلمة المرور محفوظة كبصمة PBKDF2 مع ملح داخل `functions/api/mgr.js`، وقفل 15 دقيقة بعد 5 محاولات). **الدخول بكلمة المرور أول مرة فقط**: بعدها يفعّل المدير بصمة جهازه (WebAuthn/Passkey، تُخزَّن المفاتيح العامة فقط في KV بمفتاح `mgrpk`، حتى 5 أجهزة) فيدخل بالبصمة أو الوجه. «عرض الاجتماع» شرائح بملء الشاشة (أسهم/سحب/Esc). الرمز الذي تعطيه لا يصلح لأي عملية في لوحة الإدارة. تعرض: زين الكلي، تاسك الكلي، هايبرد زين، هايبرد تاسك، وتقارير الشبكة حسب المحافظة/الكلستر/المورّد/الخطورة/التصنيف/داخلي-خارجي، مع نقر على أي رقم لعرض مواقعه، وضع عرض للاجتماعات، طباعة/PDF، وتنزيل Excel. التصنيف يعتمد على «نوع الموقع (Site Type)»: زين، تاسك، و(HYB) للهايبرد. تُحسب الأرقام في الجهاز فلا كتابة ولا طلبات إضافية على KV.

**لوحة المراقبة (تحديث):** فلاتر عامة تحكم كل الأقسام (مشغّل/نوع/محافظة/كلستر/مورّد/خطورة)، 14 تقريراً بالأبعاد (محافظة، كلستر، مورّد، خطورة، تصنيف، داخلي/خارجي، حالة الموقع، الخزانة، التقنيات، المنطقة، الفني، مدير RM، سنة التشغيل، المشروع)، جدول محوري لأي بُعدين، عبء الفنيين، فحوص جودة البيانات، آخر التغييرات (من `r.ch`)، قوائم مواقع بتصفية وترتيب وتنزيل، وإعدادات اللوحة (إظهار الأقسام، الكثافة، المظهر، تحديث تلقائي، مدة الشرائح، تشغيل تلقائي للشرائح). الدخول من أيقونة المخططات في شريط التطبيق العلوي (يُخفى بتحكم «إظهار زر لوحة المدير»). الملفات: `js/ui/{manager,mgrModel,mgrAuth}.js`.
